# System and API contracts

`create_app()` owns request validation and browser capabilities. `Database` owns SQLite transactions. The sole worker holds an advisory file lock, recovers interrupted durable jobs, atomically claims one row, and launches an isolated inference subprocess. A separate heartbeat continues while the child loads models. Progress is actual frame index/total during detection/rendering and indeterminate for model load/encoding. Cancellation checks occur every frame and the parent can terminate a stuck child. The parent applies a hard wall timeout and publishes the per-job directory only after successful exit. Restart runs from source, never partial artifacts. Output is deterministic in ownership/path semantics; numerical model output may differ across hardware/library builds.

The CLI calls the same pipeline. SQLite plus filesystem is sufficient for bounded single-host CPU work. For multiple machines, migrate owner/session/job records to PostgreSQL, artifacts to private object storage, and claims to a durable external queue; workers must use leases and fencing. Do not share this SQLite volume across hosts or start a service mesh.

## API v1

OpenAPI is generated by FastAPI at `/openapi.json`, interactive docs `/docs`. Schema versions describe results separately from API versions. Local browser `GET /api/v1/identity` creates a signed random capability cookie; no user account or biometric identification is implied.

| Operation | Route | Important semantics |
|---|---|---|
| List private sessions | `GET /sessions?offset=0&limit=20` | Own records, capped 100/page |
| Upload | `POST /sessions` | Multipart `file`; 201 or explicit validation error; content-length required |
| Session details | `GET /sessions/{sid}` | Metadata and jobs; 404 for another owner |
| Preview/source | `GET /sessions/{sid}/{thumbnail,source}` | Ownership checked; source codec may not play before transcoding |
| Submit | `POST /sessions/{sid}/jobs` | `preset`, optional four-corner calibration, `idempotency_key`; 202 |
| Status | `GET /sessions/{sid}/jobs/{jid}` | State/stage, done/total (nullable), error, worker heartbeat |
| Cancel | `POST /sessions/{sid}/jobs/{jid}/cancel` | Idempotent flag; no successful artifacts on cancellation |
| Typed analysis | `GET /sessions/{sid}/jobs/{jid}/result` | Result schema 1.1, per-PTS live measurements; ownership checked |
| Artifact | `GET /sessions/{sid}/jobs/{jid}/artifacts/{name}` | Fixed allowlist; ownership and completed-state checks; range playback |
| Add contact | `POST /sessions/{sid}/jobs/{jid}/events` | Manual annotation, bounded timestamp and display coordinates |
| Correct contact | `PATCH /sessions/{sid}/jobs/{jid}/events/{eid}` | Preserve original prediction; serialized read/replace |
| Delete | `DELETE /sessions/{sid}` | 204; scrub/tombstone, deny access, cancel, remove artifacts |

All paths above are prefixed `/api/v1`. Mutations require `X-Baseline-Request: 1`. Result/export artifacts: `result.json`, `tracks.csv`, `events.csv`, `raw-detections.json`, `annotated.mp4`, `review.mp4`. Arbitrary paths/URL ingestion are not supported. Result JSON carries PTS, display dimensions, observation state, pixel/ground coordinates, nullable scores, reason codes, calibration provenance, elapsed time, model/source checksums and warnings. Frontend types derive from this Pydantic result schema.

Durable states: `queued`, `running`, `completed`, `completed_with_warnings`, `failed`, `cancelled`. Current perception results always complete with warnings because validation is limited. Duplicate keys in a session return the same job; different payload with the same key conflicts. New keys create retries with isolated directories and never make paid calls. No two jobs process one session concurrently. Queue capacity 5 prevents unbounded waiting.

401: missing identity; 403: CSRF/origin rejection; 404: inaccessible session/job/artifact; 409: conflicting key, active session or result not ready; 411: length required; 413: upload/body limit; 415: extension not supported; 422: invalid media/calibration/event; 429: queue full; 503: worker unavailable. Validation errors from Pydantic also use 422 structured detail. Frontend shows the actual detail rather than an empty dashboard.

## Coordinates and trust

Display rotation is normalized once before analysis. A decoded frame stores original PTS and rational time_base; relative seconds subtract the first PTS. Model crops keep offsets, tensor resizing is inverted by torchvision, and original-image boxes are restored before association. Video and canvas share the exact display aspect ratio. Browser overlay selection uses the most recent frame whose PTS is at/before video presentation time; frame stepping seeks actual PTS.

Four manual correspondences fit H; independent geometry error is unknown. ORB/RANSAC drift against the first frame is checked every 15 frames: >8 display pixels or unverifiable matches invalidate calibration, clear all court meters and distances, and report a warning. This is a conservative heuristic, not a camera-cut guarantee. A strong adjacent histogram discontinuity fails the single-rally job and asks for trimming/recalibration. Cuts with similar appearance may be missed; full-match support is explicitly excluded.

Human event edits carry selected image coordinates; only confirmed/manual ground contacts may receive homography-derived court meters. Predicted bounces remain image-space hypotheses. No centimeter margins or calibrated probability claims are generated. Every line call remains uncertain in release one.
