# High-resolution import and neural tracking update

The reported MOV failed because its source resolution exceeded the former 1080p ingestion guard. The API also exposed the decoder traceback. Import now accepts bounded sources up to 4096×2160 total pixels, 100 MiB, 5–30 seconds and 1,800 decoded frames, with a 120-second isolated import deadline. Every decoded frame is checked against the source bound. It creates a browser-playable H.264 analysis preview with rotation applied, aspect preserved, even dimensions and a 1920-pixel maximum long side / 1080p pixel budget.

Source dimensions, analysis dimensions, scale, original integer PTS and rational time base are retained. All overlay/calibration coordinates refer to **rotation-normalized analysis pixels**. To recover source display coordinates, multiply x by source_width/width and y by source_height/height. Resizing never changes timestamps. Review proxies use a 90 kHz encoder/muxer time base, avoiding the 8.33 ms rounding observed with the screen recording's irregular frame times. The original upload remains local. Errors are allowlisted code/message objects, with no paths or tracebacks.

The research profile now uses a **WASB HRNet tennis checkpoint**, trained for temporal ball heatmaps, with the latest frame of three causal RGB observations as its output. It uses the exact released ImageNet normalization, affine crop and checkpoint architecture. A bounded tracklet beam associates candidates, rejects weak restarts/stationary clutter and guards discontinuous jumps. Short interpolation is still at most three frames / 100 ms. The fallback color/motion baseline remains for offline software tests, not as evidence of neural accuracy. Ball image velocity uses a least-squares trailing fit to real timestamps, rejects large residuals and never bridges unsupported gaps.

A two-second image-space trail is drawn in playback and annotated MP4. A short interpolated interval remains visibly distinct; missing intervals break the trail. A trailing path can remain visible after the ball disappears, while the current-ball indicator explicitly reports that it is not localized. This is an observed historical path, not a future trajectory or true 3D reconstruction.

Camera motion is estimated with ORB/RANSAC against the reference frame. Spatial spread, inlier count, registration residual and bounded drift are checked. Each supported frame receives its **own transformed court calibration**; unsupported frames receive null ground geometry. Player speeds, minimap points and reviewed contacts use that timestamp's mapping. A matching residual is not independent court accuracy. Camera cuts remain unsupported. The previous global invalidation behavior is superseded; stale homographies are never retained as current geometry.

[Pose and player identity](pose.md) and [Shot Quality semantics](shot-quality.md) describe the remaining measurement limits. Public example evaluation and private-video execution outcomes are recorded in [verification](verification.md). No model's published benchmark number is represented as accuracy on the user's footage.

The side shot card shows a current/past-two-second **image-coordinate** court/ball view, estimated stroke type and image speed. A missing current image derivative may display a previous valid sample for at most 150 ms, explicitly marked with age; raw data stays null. Physical speed entries are separately attributed measurements. Stroke type uses pose/wrist proximity and a right-handed assumption, so it is labeled estimated. This is not a trained tennis action classifier.
